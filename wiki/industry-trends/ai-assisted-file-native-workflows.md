# AI-Assisted File-Native Workflows

## Current understanding

<!-- stage1-placeholder: single-source lead; Stage 2 will synthesize from accumulated EvidenceItems -->
AI systems are being integrated as helpers inside file-native workflows rather than replacing the host application. In this pattern, the model reads and writes structured local artifacts such as markdown, canvas files, or database-like documents while the primary app continues to own the user experience. The operational goal is portability, inspectability, and reduced lock-in.

## Supporting Data Points

- Obsidian Skills targets .md, .base, and .canvas files.
- The workflow stores skills in a /.claude directory inside the vault.
- The article explicitly contrasts this with proprietary app databases.

## Time sensitivity

Relevant as of 2026-01-16; likely to remain meaningful while local-first knowledge tools and agent clients keep using file-based interfaces.

## Uncertainty / maturity

The source is a single product-focused article, so it does not prove broad adoption; it shows a plausible integration pattern with limited evidence of scale.
