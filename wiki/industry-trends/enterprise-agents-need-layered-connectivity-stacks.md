# Enterprise Agents Depend More on Layered Connectivity

## Current understanding

<!-- stage1-placeholder: single-source lead; Stage 2 will synthesize from accumulated EvidenceItems -->
Production agent systems increasingly separate connectivity into complementary layers rather than relying on one universal interface. Reusable procedure, local command execution, and governed external integration each solve different parts of the workflow. This changes agent architecture from single-abstraction design toward stack selection based on task shape, control needs, and token cost.

## Supporting Data Points

- Skills are described as reusable procedural instructions.
- CLI is described as token-efficient and composable.
- MCP is described as the enterprise integration layer with governance and audit trails.

## Time sensitivity

Actionable as of 2026-05-02; relevant while enterprise agents continue moving from demos into production systems with mixed tool and governance needs.

## Uncertainty / maturity

The source presents this as an architectural recommendation, not a comparative study across many production deployments. Different organizations may collapse layers differently depending on tooling maturity and security requirements.
