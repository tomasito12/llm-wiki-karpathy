# Procedural Knowledge for Agents

## Current understanding

<!-- stage1-placeholder: single-source lead; Stage 2 will synthesize from accumulated EvidenceItems -->
Procedural knowledge is know-how: the stepwise order, judgment, and execution rules needed to complete a task reliably. In agent systems, it complements factual retrieval and tool access by telling the model what to do, when to do it, and in what sequence. This is important whenever tasks are repeatable but too process-heavy to encode in a single prompt. The durable design lesson is that agents need instruction structure, not just more facts.

## Examples

“Skills (Domain Knowledge): Reusable procedural instructions and markdown files that teach the model how to use tools.”

## Key Points

- Procedural knowledge is about action order and judgment, not stored facts.
- A skill can encode repeatable workflows that are awkward to restate in every prompt.
- The concept pairs naturally with RAG for facts and MCP for tools.
- It is most useful for tasks that require consistent execution rather than open-ended creativity.
- Procedural instructions can be portable across clients and repositories.
- Skills can be written by humans or generated by agents.
- The value is in reusable task guidance, not just static documentation.

## Operational Insight

Use procedural modules when the goal is reliable execution of repeatable workflows, especially where the model must preserve order and judgment across steps. Keep the process explicit so the agent does not have to infer the workflow from raw examples or ad hoc prompting.
