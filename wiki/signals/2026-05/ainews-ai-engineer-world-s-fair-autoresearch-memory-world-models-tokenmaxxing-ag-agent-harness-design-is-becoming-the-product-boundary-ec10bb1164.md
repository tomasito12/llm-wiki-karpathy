# Agent harness design is becoming the product boundary

## Signal

### Summary

The roundup repeatedly shows that models are being judged through their surrounding runtime: compaction, durable execution, browser use, HITL, subagents, and state management. The point is not that models stopped mattering, but that operational usefulness depends heavily on how the model is wrapped and controlled.

### Why It Matters

As of 2026-05-02, teams building agents should expect most differentiation to come from runtime design and workflow integration, not from a model endpoint alone. That changes architecture priorities toward orchestration, memory, and supervision.

### Operational Relevance

Designing the agent harness is now a first-order systems task: state handling, tool discipline, pause/resume, and retry behavior can matter as much as model choice.

### Service Automation Relevance

Service automation stacks will need stronger orchestration and intervention controls because support workflows depend on repeatability, auditability, and safe handoffs.
