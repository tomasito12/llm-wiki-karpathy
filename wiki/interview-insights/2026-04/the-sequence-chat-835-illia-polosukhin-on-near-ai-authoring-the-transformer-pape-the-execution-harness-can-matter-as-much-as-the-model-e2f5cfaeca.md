# The execution harness can matter as much as the model

## Interview Insight

### Summary

Across the interview, Polosukhin returns to the idea that the harness around a model is crucial. He points to examples where a smaller model improved coding performance by 10x just by changing how it edited files, and he says the agent harness will change how people interact with computing. The core point is that agent reliability and usefulness can be dominated by workflow design, tool discipline, and execution context rather than parameter count alone.

### Why It Matters

As of 2026-04-02, this is one of the most reusable engineering lessons in the transcript. It supports investing in orchestration, tool use, and environment design as first-class product surfaces, especially for local and privacy-preserving agents.

### Operational Relevance

Focus on file operations, tool boundaries, and execution environments when improving agent performance. For coding or workflow agents, changes to the harness may produce larger gains than model swaps, so evaluation should isolate harness effects from model effects.

### Service Automation Relevance

Highly relevant for chatbots and voicebots: the surrounding workflow, handoffs, and tool access can determine service quality as much as the language model. Better harness design may improve resolution rates and reduce brittle behavior in customer-facing automation.
