# Agent-heavy developer platforms need bidirectional UI and agent-facing APIs

## Interview Insight

### Summary

Rodriguez argues that a GitHub-like product can no longer rely on human-to-human collaboration primitives alone. He says the API layer needs to become agent-centric and the UX layer needs to support bidirectional action: the agent can affect the UI, and the UI can trigger agent behavior. Copilot canvases are presented as an early example of this agent-experience layer, or AX.

### Why It Matters

This is a durable product architecture lens as of 2026-06-06: once agents participate in the workflow, the interface is no longer just for display and clicks. The interesting design problem becomes shared control across human and agent, which is more general than code generation and applies to any tool where the model must both read and act.

### Operational Relevance

For developer tools, the implication is to design surfaces where tasks, actions, and feedback can flow in both directions, not just through a chat sidebar. That affects API design, state management, review mechanics, and how actions are exposed to the model.

### Service Automation Relevance

The same pattern applies to service tooling if an agent can both read a case context and trigger UI actions, while humans can still intervene through the interface. It suggests a path beyond pure chatbots toward bidirectional operator-assist systems.
