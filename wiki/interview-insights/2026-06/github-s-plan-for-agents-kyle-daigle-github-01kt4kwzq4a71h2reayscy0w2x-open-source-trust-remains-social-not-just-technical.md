# Open-source trust remains social, not just technical

## Interview Insight

### Summary

Daigle argues that PR verification, stars, commit counts, and other passive signals do not fully solve trust in open source. He says trust is diffuse once agents write and review code, and maintainers still rely on human judgment, project norms, and project-specific rules.

### Why It Matters

As of 2026-06-02, this is a strong warning against treating verification as a purely technical checkbox. For agentic coding and open-source intake, durable trust systems need both machine verification and social approval mechanisms that fit each project’s norms.

### Operational Relevance

Design approval-based workflows where maintainers define their own trust signals, rather than forcing a universal gate. Combine verification tooling with human review, maintainers’ heuristics, and project-specific policies for accepting agent-generated changes.

### Service Automation Relevance

Service automation has the same pattern: automated outputs can be checked for correctness, but customer-facing trust still depends on escalation rules, accountability, and human-visible approval paths. Verification alone does not create user confidence.
