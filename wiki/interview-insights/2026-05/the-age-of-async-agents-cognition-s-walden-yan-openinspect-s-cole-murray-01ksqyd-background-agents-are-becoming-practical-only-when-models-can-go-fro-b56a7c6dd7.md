# Background agents are becoming practical only when models can go from spec to PR with low friction

## Interview Insight

### Summary

The speakers tie the shift toward background agents to a model capability jump around December 2025, when Opus 4.5 and GPT 5.2 made it feasible to move from a specification to a completed pull request with much less handholding. They treat that as the point when cloud execution became a practical workflow rather than a demo pattern. The important part is not just better generation, but enough autonomy to keep the work off the developer’s local loop.

### Why It Matters

As of 2026-05-28, this marks a durable threshold for agent adoption: teams can start optimizing around end-to-end PR completion instead of autocomplete. It shifts the product question from "can the model code?" to "can the system run unattended with acceptable control?"

### Operational Relevance

Useful for architecture decisions around background execution, agent scheduling, and when to move tasks out of the IDE into a control plane. It suggests that orchestration, permissions, and verification become the main bottlenecks once spec-to-PR is viable.

### Service Automation Relevance

Indirectly relevant: the same autonomy threshold applies to support or operations workflows that need multi-step completion rather than single-turn replies.
