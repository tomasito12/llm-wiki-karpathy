# Memory is still an unsolved retrieval problem, with file-like workarounds as a plausible direction

## Interview Insight

### Summary

Cole says memory is not solved and describes current practices such as skills and Claude.md-style instructions as partial gaps. Walden adds that memory generation and retrieval are both hard, especially because the system should avoid storing overly specific or overly broad facts. One proposed direction is to make memory feel more like a file system that the agent can navigate natively.

### Why It Matters

As of 2026-05-28, this is a durable caution against treating agent memory as a solved product feature. It suggests that teams should prefer explicit files, skills, and editable knowledge stores over opaque long-term memory claims until retrieval quality is proven.

### Operational Relevance

Builders should expect memory to require pruning, retrieval evaluation, and strict scope controls. File-native memory or versioned knowledge artifacts may be easier to maintain than free-form hidden memory blobs.

### Service Automation Relevance

Relevant to long-running support or PM agents because they need durable issue context, but the transcript implies those systems should still expose editable artifacts and not rely on magical memory.
