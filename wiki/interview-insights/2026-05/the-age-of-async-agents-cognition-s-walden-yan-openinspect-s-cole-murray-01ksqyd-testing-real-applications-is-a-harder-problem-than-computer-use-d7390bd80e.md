# Testing real applications is a harder problem than computer use

## Interview Insight

### Summary

Walden Yan distinguishes basic computer-use from end-to-end testing. In the transcript, testing means orchestrating app state, services, permissions, feature flags, and multi-step flows so the agent can prove a change actually works. He also says no single frontier model always solves the whole workflow, so systems sometimes need multiple models and explicit orchestration to finish the test loop.

### Why It Matters

As of 2026-05-28, this is one of the clearest operational lessons for agentic coding: demo-quality UI navigation is not the same as verifiable software validation. Teams that care about reliability need test harnesses, screenshots or video, and workflow-specific orchestration rather than raw model capability alone.

### Operational Relevance

This supports investing in verification loops, app-specific test runners, and structured success criteria. It also implies that agent evaluation should measure completed workflows, not just generated code or browser clicks.

### Service Automation Relevance

Highly relevant to support automation because customer-facing agents also need to validate outcomes across systems, not just produce a plausible answer.
