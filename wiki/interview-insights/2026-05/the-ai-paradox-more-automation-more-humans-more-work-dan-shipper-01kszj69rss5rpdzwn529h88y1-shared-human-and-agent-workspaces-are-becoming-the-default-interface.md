# Shared human-and-agent workspaces are becoming the default interface

## Interview Insight

### Summary

Shipper predicts that work will bifurcate into two patterns: a delegated agent that can do tasks asynchronously, and a computer-native workspace such as Codex or Claude Code where humans and agents work on the same artifact together. He says the browser should live inside the agent, not only the agent inside SaaS, so the model can inspect and act on the same context as the user. This is presented as a practical interface shift, not just a naming change.

### Why It Matters

As of 2026-05-24, this reframes product design for AI-native workflows. The durable lesson is that useful agent systems need shared state, visibility, and co-editing surfaces instead of a one-way chat box. Teams building developer tools, productivity software, and internal automation should expect the agent to become part of the working surface itself.

### Operational Relevance

Products should support synchronous human-and-agent collaboration: visible state, in-app browsing, logs, approval queues, and rollback. The transcript suggests that a browser embedded in the agent workspace can unlock research, editing, and operational tasks without switching contexts. This also implies that many apps should be optimized for being acted on by both the human and the agent.

### Service Automation Relevance

For support and service workflows, this points toward agent workspaces that let human operators inspect, approve, and correct automated actions in one place. It supports handoff designs where the AI can gather context and the human can intervene without re-entering the entire case.
