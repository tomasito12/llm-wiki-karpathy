# Drone autonomy is a layered capability, not a single feature

## Interview Insight

### Summary

The transcript breaks drone autonomy into five operational levels: terminal guidance, bombing, autonomous target detection and engagement, autonomous navigation, and autonomous takeoff and landing. The point is that different autonomy layers solve different failure modes, so "autonomy" should not be treated as one undifferentiated product claim. This framing is useful because it maps model capability to mission design rather than to a generic autonomy label.

### Why It Matters

Actionable as of 2026-05-18 because it gives a reusable decomposition for evaluating autonomous systems in adversarial settings. For AI engineering, it encourages measuring which part of the workflow a model actually replaces, instead of assuming end-to-end autonomy. That is a durable way to reason about capability boundaries, deployment risk, and staged rollout.

### Operational Relevance

Use the autonomy ladder to separate last-mile perception, decision, navigation, and actuation in system design. It suggests that evaluation and failure analysis should be per-level, since terminal guidance can succeed even when full navigation or target selection is not solved. It also implies that productization can proceed incrementally instead of waiting for full autonomy.
